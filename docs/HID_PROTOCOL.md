# LAMZU Thorn V2 & 8K Dongle V2 HID通信プロトコル仕様書（非公式）

本書は、LAMZU Thorn V2 マウスおよび LAMZU 8K Dongle V2 におけるUSB HID通信仕様の調査結果をまとめた技術資料です。本資料は独自に調査・検証した内容であり、LAMZU公式の仕様書ではありません。

---

## 1. デバイス識別情報

- **対象製品**: LAMZU Thorn V2 (ワイヤレスゲーミングマウス)
- **接続方式**: LAMZU 8K Dongle V2
- **Vendor ID (VID)**: `0x37B0`
- **Product ID (PID)**: `0x002E`

### 主要インターフェース構成
1. **MI_00 (Col01)**: マウスポインター・ボタン入力用標準HID
2. **MI_01 (Col04)**: ベンダー定義通知インターフェース
   - Usage Page: `0xFFA0`
   - Usage: `0x0001`
   - 用途: バッテリー残量・充電状態の受動的 Input Report 受信
3. **MI_02**: ベンダー定義設定管理インターフェース
   - Usage Page: `0xFFFF`
   - Usage: `0x0000`
   - 用途: Feature Report によるオンデマンド設定読み取り（DPI、ポーリングレート）

## 2. バッテリー残量・充電状態（受動的 Input Report）

ドングルは、マウスからの状態更新を契機として以下の Input Report（Report ID: `0x04`、長さ9〜10バイト）をホストへ送信します。

### 2.1 形式A：通常バッテリー通知パケット
- **先頭バイト（Payload[0]）**: `0x38`
- **パケット構造（実測値と推定）**:
  ```text
  Byte 0: 0x04 (Report ID)
  Byte 1: 0x38 (形式A ヘッダー)
  Byte 2: 内部通信・動作状態コード（実測値: 0x02, 0x03 等）
          ※実測事実: USB充電ケーブル未接続時でも 0x03 が観測されている
            (例: 04 38 03 00 54 5E 00 A5 D1)。
            したがって 0x03 を単純に「充電ケーブル接続中」と断定できず、
            マウス内部の通信リンクやサブステータスを示すコードであると推定。
  Byte 3: 充電ステータスフラグ（実測値）
          - 0x04: 充電中（USB給電検知）
          - 0x00: 非充電（通常バッテリー駆動）
          ※本アプリでは、この Byte 3 を充電判定の主要基準として採用。
  Byte 4: 変動状態値（実測値: 0x54, 0x84 等）
  Byte 5: バッテリー残量（実測値: 0〜100% の10進数値）
          - 例: 0x5E = 94%, 0x5F = 95%, 0x61 = 97%, 0x64 = 100%
  Byte 6〜8: チェックサム / 補助バイト
  ```

### 2.2 形式B：状態変化補助パケット
- **先頭バイト（Payload[0]）**: `0x03`
- **パケット構造**:
  ```text
  Byte 0: 0x04 (Report ID)
  Byte 1: 0x03 (形式B ヘッダー)
  Byte 2: バッテリー残量（存在する場合）
  Byte 3: 充電フラグ（0x00: 非充電, 0x01: 充電中）
  ```
- **注意点**: 形式Bパケット受信時は、残量0%の誤認を防ぐため残量パーセントの更新は行わず、充電フラグの反映および受信タイムスタンプの更新のみを行う。また、ドングル再接続直後の待機中（WAITING_DATA）は形式Bのみで正常受信中（NORMAL）へ復帰させず、形式Aの到達を待つ。

### 2.3 ケーブル取り外し後の充電表示に関する挙動（観測事実と留意点）
- **表示上の観測事実**:
  - USB充電ケーブルを取り外した後も、ステータスパネルやトレイアイコンに充電中表示が継続する場合がある。
  - ケーブル抜去後にマウスを動かしたりクリックしたりしても、直ちに充電中表示が解除されないことが実機で確認されている。
  - 同様の現象は本アプリケーションだけでなく、**LAMZU 8KドングルのLEDインジケーター**および**LAMZU公式Webドライバー（LAMZU Aurora）**上でも確認されている。
- **解析・設計上の留意点**:
  - 現時点で原因は未確定（ハードウェア、ドングル、ファームウェア側の仕様・挙動の可能性）であり、特定の解除条件は確立されていない。
  - 本アプリケーションはデバイスおよびドングルから受信した最新のInput Reportの値をそのまま忠実に反映する設計方針を採っており、推測による強制的な充電解除処理は行わない。

## 3. デバイス設定の読み取り（オンデマンド Feature Report）

ステータスパネル表示時に、MI_02（Usage Page: `0xFFFF`, Usage: `0x0000`）に対して Feature Report（Report ID: `0x00`、65バイト）を送信することで、現在の設定値を読み取る。

### 3.1 通常アプリの送信許可コマンド（読み取り専用ホワイトリスト）

本アプリケーションの通常稼働時において、送信が許可されているコマンドは以下の3点のみである（書き込み・設定変更コマンドは一切除外）。

| コマンド | 名称 | 用途 |
|:---:|---|---|
| `0x80` (128) | GET_POLLING_RATE | 現在設定されているポーリングレートの取得 |
| `0x81` (129) | GET_DPI_STAGES | DPIプリセット（ステージ一覧）の取得 |
| `0x82` (130) | GET_ACTIVE_DPI | 現在選択されているDPIステージ番号（1〜N）の取得 |

### 3.2 ポーリングレート変換テーブル (0x80)

| 受信コード | ポーリングレート (Hz) |
|:---:|:---:|
| 8 | 125 Hz |
| 4 | 250 Hz |
| 2 | 500 Hz |
| 1 | 1000 Hz |
| 32 | 2000 Hz |
| 64 | 4000 Hz |
| 128 | 8000 Hz |

### 3.3 DPIステージ取得 (0x81 / 0x82)
- `0x82` レスポンスの `Byte 8` から現在のアクティブステージ番号（1始まり）を取得。
- `0x81` レスポンスの `Byte 8` から有効ステージ総数を取得し、各ステージのDPI値（16ビットビッグエンディアン: `(Byte[idx] << 8) | Byte[idx+1]`）を抽出。
- アクティブステージ番号に対応するDPI値を現在のDPIとして特定。

### 3.4 調査用コマンド (0x83) と運用上の扱い
- `0x83` (GET_BATTERY_PERCENT):
  Aurora公式Webドライバーの通信解析およびプロトコル検証時に確認された残量・充電状態能動取得コマンド。
- **運用上の区別**:
  本アプリケーションの通常稼働コード（`device_query.py`）の送信許可リスト（`ALLOWED_READ_COMMANDS`）には `0x83` を**含めていない**。
  USBバス帯域の節約および無線干渉を回避するため、バッテリー監視はすべて受動的 Input Report（セクション2）のみで行い、能動ポーリングは一切実行しない。
